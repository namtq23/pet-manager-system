# Plan 02-01: Supabase Schema Migration, Models & Repositories (Customer & Pet Data Layer)

**Phase:** 02 - Quản lý Khách hàng & Thú cưng (Customer & Pet Management)
**Requirement IDs:** CUST-01, CUST-02, CUST-03
**Target Architecture:** Flutter Web + Supabase (PostgreSQL BaaS)

---

## 🎯 Plan Goal
Khởi tạo cấu trúc cơ sở dữ liệu PostgreSQL cho Khách hàng (`customers`) và Thú cưng (`pets`) trên Supabase với Row Level Security (RLS) policies, đồng thời xây dựng các Data Models và Repositories phía Flutter để thực thi CRUD và tra cứu SĐT nhanh.

---

## ⚡ Task Breakdown

### Task 1: Supabase Database Migration (`customers` & `pets`)
- **File:** `supabase/migrations/20260824100000_create_customers_and_pets_schema.sql`
- **Actions:**
  1. Tạo bảng `public.customers` với các trường: `id` (UUID PK), `full_name` (TEXT NOT NULL), `phone` (TEXT NOT NULL UNIQUE), `address` (TEXT), `notes` (TEXT), `created_at`, `updated_at`, `created_by`.
  2. Tạo bảng `public.pets` với các trường: `id` (UUID PK), `customer_id` (UUID FK -> `customers.id` ON DELETE CASCADE), `name` (TEXT NOT NULL), `species` (TEXT), `gender` (TEXT), `age` (TEXT), `weight` (NUMERIC), `notes` (TEXT), `avatar_url` (TEXT), `created_at`, `updated_at`, `created_by`.
  3. Đặt Indexes: `idx_customers_phone`, `idx_customers_full_name`, `idx_pets_customer_id`, `idx_pets_name`.
  4. Bật RLS và thêm Policies cho phép Active Doctors/Admins quản lý toàn bộ dữ liệu.

### Task 2: Data Models (Customer & Pet)
- **Files:**
  - `frontend/lib/features/customer/models/customer.dart`
  - `frontend/lib/features/customer/models/pet.dart`
- **Actions:**
  1. Xây dựng model `Pet` với `fromJson`, `toJson`, `copyWith`.
  2. Xây dựng model `Customer` chứa thông tin cá nhân và danh sách `List<Pet> pets`, hỗ trợ `fromJson`, `toJson`, `copyWith`.
  3. Tuân thủ 30 dòng/hàm.

### Task 3: Customer & Pet Repositories
- **Files:**
  - `frontend/lib/features/customer/repositories/customer_repository.dart`
  - `frontend/lib/features/customer/repositories/pet_repository.dart`
- **Actions:**
  1. Impl `CustomerRepository`:
     - `normalizePhone(String phone)`: Loại bỏ ký tự không phải số (`RegExp(r'\D')`).
     - `searchCustomers(String query)`: Tìm kiếm theo SĐT (hoặc Tên gần đúng), bao gồm thông tin `pets(*)`.
     - `createCustomer(...)`: Tạo khách hàng mới (bắt lỗi `23505` trùng SĐT -> ném Exception `DUPLICATE_PHONE`).
     - `updateCustomer(...)`: Cập nhật thông tin chủ nuôi.
  2. Impl `PetRepository`:
     - `addPet(...)`: Thêm cún mới gắn với `customerId`.
     - `updatePet(...)`: Cập nhật thông tin cún.
     - `deletePet(...)`: Xóa hồ sơ cún.
  3. Gắn tag EARS trong code (`// EARS[Ubiquitous]`, `// EARS[Event]`, `// EARS[Unwanted]`).

## 🔍 Verification Criteria
1. Migration file SQL tạo đủ 2 bảng, Indexes, RLS Policies không có lỗi cú pháp.
2. Dart Models parse JSON chính xác, hỗ trợ danh sách `pets` lồng trong `Customer`.
3. Repository xử lý chuẩn hóa SĐT và map đúng lỗi `DUPLICATE_PHONE` khi trùng SĐT.
